# 图片文字工作流 v0.5 开发验收

本版将图片文字抽取与图片文字合入分为两个Skill，在项目初始化时保存是否接入图片翻译的选择。常规文本、图片原文和图片翻译状态保持独立；引擎导入由既有game-repack负责。

## 已完成

- PP-OCRv6 medium全量扫描，子进程退出后才加载本地Qwen3-VL 8B；选择性复核和抽查，而非全部图片再送Qwen。
- 只有经过小样本视觉校准的普通字体资源族才能走普通候选路线；未知资源不因高分自动放行。极小像素字和故障残字进入Agent争议队列。
- 当前多模态对话Agent读取本地图像任务包、确认原文和坐标，程序绑定来源与证据；双模型一致不充当视觉确认。未辨认项可复核并保留历史，已确认项拒绝冲突覆盖。
- 确认原文导出单列CSV与mapping，隔离子工程复用正式翻译流程；译文行数、哈希和完整语义验收报告通过才允许收回并合入。
- 输出同尺寸中文PNG或运行时overlay描述，检查字体字形和排版容量；默认灰色蒙版alpha=224，可配置。输出明确标为ready_for_engine_adapter、installed=false。

## 真实小样本闭环

证据保存在本机忽略目录 `verification/tiered_e2e/`，不提交游戏素材或模型。

| 步骤 | 实际结果 |
|---|---|
| 输入 | 5张：中英文正常文字对照、艺术字海报、GAME OVER像素字、无字树木 |
| GPU OCR | 全部5张，0错误；当时适配器版本4，约13.8秒含初始化 |
| 分流 | 2张普通候选、1张直接Agent、2张Qwen（含无字抽查） |
| 本地Qwen | 2次真实请求，约22.1秒；海报含字，树木无字 |
| 第三层 | 对话Agent实际查看图像，确认4张含字图；human_approval=false |
| 导出 | 4条单列原文、4处映射，需处理范围内未决0 |
| 续跑 | 已完成Qwen批次复用1，执行批次0，新增请求0 |

该测试为了覆盖普通候选路径显式将ordinary_samples设为0；生产默认仍抽查普通候选。普通中英文图为程序排版对照。样本是目的性开发集，不能据此推断新游戏准确率或1666张素材的节省比例。模型与硬件沿用此前20张对照实验记录。

## 修复与静态合入验证

- 用户原始报纸截图重新以适配器版本5进行真实GPU OCR，0错误，约13.3秒含初始化。合并后区域数从旧版本29降到24；标题中的分块后缀重复已消除，报头仍存在误读，须继续视觉复核，不能称全文识别正确。冲突片段保留原框及替代读法。
- 罗马数字III不再被重复字母规则筛除；无效重复LLLL仍被筛除。
- 正常英文控件图输出中文PNG和overlay清单，检查了实际PNG；可变字体调整到常规字重400，中文在灰色蒙版上可读，区域外保留原图。
- 排版用的译文与验证报告是明确标注的测试夹具，并非真实游戏正式翻译验收；未启动游戏正文翻译、未安装资源、未控制桌面。
- 项目初始化在空目录夹具实测：disabled选择写入localization_project.json，并纳入初始Git提交。
- 自动测试58项通过；两个新增Skill通过skill-creator结构校验。测试覆盖路由、证据篡改、缓存绑定、未决修订、源文隔离、正式译文哈希门槛、缺字/溢出、图片保持和未安装状态。

## 使用与边界

入口与命令见[工具说明](../README.md)，策略依据见[三级工作流](../WORKFLOW.md)。两个Skill位于工作区 `.agents/skills/game-image-extract/` 与 `.agents/skills/game-image-repack/`。

尚未自动识别所有字体资源族，也没有跨引擎通用导入器。弱信号和未检出仍属于预测排除，需抽查，不保证零漏检。当前Agent看图由对话执行，无额外付费视觉API调用；不能把任务包生成当成完成看图。
