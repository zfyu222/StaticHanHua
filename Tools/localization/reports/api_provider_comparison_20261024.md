# yjapi 与 DeepSeek 官方审校对照（2026-10-24）

**本次没有观察到 yjapi 比官方更差。** 同一批10条文本、同一份改动前审校提示，两边各运行两次；每一次均修正5条已知错误、保留5条正确译文。不能把这个结果推广为两边整体质量相同，也不能据此断言历史漏判来自廉价接口。

## 控制条件

- 使用本机已配置的命名API `yjapi` 和 `deepseek`，没有修改默认接口、密钥、思考或并发。通过共用`run_api(..., api_name=...)`执行完整的输入生成、请求、解析、落盘与整轮审校。
- 原文、旧译、背景、空术语夹具、输出契约相同；采用先前的legacy提示，避免将本轮新提示与接口同时改变。没有独立解读参考，也没有把案例类别或预期答案作为记录诊断发给API。
- 四次实际请求的system/user消息SHA-256完全一致。system为空串，全部生成指令和数据位于user消息。消息一致不表示服务内部处理一定相同。
- 实际参数均为thinking enabled、reasoning_effort high、temperature 1、max_completion_tokens 65536、配置并发25。配置的模型名不同，未强行改名；yjapi为`deepseek-v4.1-flash`，官方为`deepseek-flash`。
- yjapi配置非流式、300秒超时；官方配置流式、200秒超时，保持原样。本次无超时、连接失败、格式失败或重试。
- 按yjapi → 官方 → 官方 → yjapi交错执行，避免把接口和先后顺序完全重合。预先上限8次出站，实际4次，随后停止。

## 能说明与不能说明的事

当前这组案例未复现yjapi漏判，**没有支持“官方在这组审校上质量更高”的证据**。这也不能反向证明yjapi没有质量问题：样本少、是选出的回归案例、同一批重复两轮，并非40条独立样本；旧提示本就含头皮短发茬例子。皱眉、皱纹及对应字面正确对照未写进提示，但难度与规模仍有限。不涵盖术语提取、全文初译、所有文体或长期稳定性。

官方文档说明`deepseek-flash`当前由DeepSeek-V4.1-Flash-1017提供服务。[官方说明](https://api-docs.deepseek.com/api/responses) yjapi请求并回显`deepseek-v4.1-flash`，无法从名称证明它使用相同更新版、部署精度或推理过程。本测试比较的是用户当前两套接口配置的实际表现，不是鉴定转发后端真伪。先前失败调用的供应商、后端版本或路由不能仅用当前配置及回显名称反推。
