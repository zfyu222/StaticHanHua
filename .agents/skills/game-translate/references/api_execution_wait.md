# API 阶段自动多轮与原生等待

API 路线默认由一个新的 Luna 执行代理管理一个阶段的常规多轮，主代理只派发一次任务，然后进入原生代理等待。程序在同一进程内调用已有整轮检查与失败项重派入口，复用内存缓存；不在各常规轮之间唤醒主 AI。质量规则、Sol 验收及整轮修复边界不变，范围和停止条件见 [自动循环边界](api_cycles.md)。

## 主代理

1. 核对项目、当前阶段和待执行轮次，没有需要先恢复的旧请求。只有用户已选择并授权 API 执行时才派发实际运行。
   核对选路授权：已有优先级时默认命令不带 `--api`，由程序按配置选路。主代理不能把自行选择接口的决定交给执行代理。仅用户明确点名接口才允许 `--api <名称>`；恢复任务也不例外。超时、格式失败、推理耗尽不构成切官方或扩大费用边界的授权。
2. 创建 `gpt-6-luna`、`fork_turns=none` 的执行代理。只交付绝对项目路径、阶段、Python 路径、下面的执行模板和必要的显式恢复 session ID。不要复制主对话历史、术语表、批次 JSON、API 密钥或日志。普通翻译 API 的模型仍由 api.local.jsonc 决定；Luna 是程序执行角色，不冒充正文 API 模型。
3. 主代理用当前宿主提供的 `wait_agent` 或同等原生等待接收完成事件。等待挂起期间不主动推理检查状态，不调用 list_agents、status、tail、write_stdin 或读取 receipt 来探测进度；不反复询问执行代理，也不用周期 Sleep 猜测程序是否结束。保持本轮对话等待，不先发 final 后假设外部文件能自动唤醒聊天。
4. 等待时长在宿主允许范围内尽量延长；宿主有更高优先级的最大等待或沟通约束时按其上限设置。等待超时而没有事件，只继续原生等待，不追加状态查询或“还没完成”的分析。用户询问进度时简短回应；明确要求状态才按需查询一次，不取消或重启原任务。
5. 只在本阶段普通循环完成、明确失败、需要主流程决策或用户新指令时处理结果。读取一次紧凑通知及必要 receipt，检查 next_action、stage_clean 及升级派发信息；translate 完成后先由主 AI 检查或提交，再单独调用 draft_check；draft_check/review/final_review 内的扫描和后续常规轮已由程序调用，不为每轮重启 runner。试译决定、术语冻结、阶段切换及 Sol 任务仍由主流程负责。完成后释放本阶段执行代理，下一阶段调用新建，避免监控历史累积。

试译本轮翻译结束后调用 pilot-report，由主 AI 阅读原译文、机械诊断和任务状态，整体判断流程、风格及共性错误，用 pilot-decide 记录 accept/retry/stop。按需调整方案后明确 pilot-retry；不自动派独立审校或逐句修复。执行代理仍只负责进程等待。正式阶段普通质量修复按原规则整轮处理，默认累计 6 轮后升级 Sol。

不得承诺完全零唤醒、零 Token 或程序退出必然唤醒所有宿主；超时、新消息和平台行为都可能恢复主代理。没有可用 Luna 槽位时先等待现有代理结束；不要额外创建 Sol 调度代理。宿主不支持原生代理等待时明确说明能力缺口，退回有界工具等待，不假称具备事件回调。

## 给 Luna 的最小执行模板

> 你只负责运行一个 API 阶段的自动常规循环，并等待该进程结束。项目：`<绝对路径>`；阶段：`<stage>`；Python：`<绝对路径>`。
>
> 执行一次：`<python> D:/StaticHanHua/Tools/localization/run_api_round.py --project <project> --stage <stage>`。以工具的参数数组或正确 shell 引号传递路径，不拼接不可信命令。显式恢复时才附主流程已核实的 `--sessions <IDs...>`。
>
> runner 自行阻塞等待子进程，日志留在项目内；不再启动第二个 runner，不运行 status/tail 或定时读取文件。优先使用阻塞式工具等待。如果命令工具返回 session ID，在同一程序化工具调用内以 await 等待该 session 结束，必要的有界续等留在执行代理，不逐次上报给主代理。不要把短间隔轮询搬到你的推理中。
>
> 按用户原优先级运行，不自行添加 `--api`；只有主流程同时提供用户明确指定该接口的授权依据时才允许固定接口。错误不构成切换官方、修改优先级或增加请求/Token/尝试预算的授权。收到用户停止消耗的指令时立即终止本任务 runner 及其子进程，不重试、不恢复。
>
> 不查看密钥文件，不翻译或修改结果，不跑质量裁决，不自行额外执行命令、切换阶段或放宽门槛；本阶段普通修复轮由 runner 内部程序自动推进。错误、锁冲突、不明在途请求及 Sol 升级均只报告，不自行重放付费请求。
>
> 等待期间不向主代理发送心跳、进度或“仍在运行”；只在完成、失败或需决策时发送一次终结结果。返回 `status`、`stage`、`receipt_file`、简短计数/阻塞原因；不返回原文、整批译文、提示词或完整日志。不需要调用 send_message；原生最终结果通知即可。

## 程序入口与边界

runner 的程序日志默认包含性能计时、每 10 个工作单位或事件间隔超过 30 秒的进度，以及末尾总用时与 Token 总结；这是本地程序事件日志，不要求主代理或执行代理轮询、发送心跳或定期读取。回执新增 profile_log、profile_summary、elapsed_seconds 和 performance；JSONL 位于 logs/api_runs，完整性能汇总位于 reports/api_runs。Token 区分本轮与项目累计，未知用量不得当零消耗；失败回复和重试的已报告用量也计入，缓存/推理子项不重复累加。

`run_api_round.py` 使用 Popen + wait 阻塞等待 translation_workflow.py run-api，一次调用执行一个阶段的普通多轮，不自动串联语义阶段。translate 只收齐草稿后交回主 AI；程序审校单独使用 --stage draft_check。draft_check/review/final_review 默认自动检查与常规返修；`--single-round` 仅作调试。stdout/stderr 写入 `TranslateFiles/logs/api_runs/`，最终 receipt 写入 `TranslateFiles/reports/api_runs/`，对工具只输出一份 JSON 回执。Python run_api 的 continuous=False 对应调试单轮。

`completed` 仅表示本轮 API 执行正常返回、没有暂停/待处理异常/在途交接，不代表全文质量通过。传输重试已经成功时 failed 计数可能非零；不能因此重译通过项。`needs_attention`、`failed`、`interrupted` 交主流程按现有恢复协议处理，不自动再次运行。

`TranslateFiles/state/api_round.lock` 防止重复启动包装器；普通启动不回收异常遗留锁。显式 `--resume` 时先核对旧 owner_pid 和子进程 pid 均已结束，才回收锁并接续：已有完整回复先收集，成功提交任务跳过，其余未完成任务按原尝试预算重试。不能仅因锁时间久就重新请求。该锁只保护通过本入口启动的轮次；所有 API 自动执行统一走本入口，不另行直接启动重叠的 run-api。

文件 receipt 本身不是 Codex 唤醒事件；真正通知来自 Luna 的原生完成事件。工具内部的进程等待/有界续等是程序行为，不等于主代理反复生成推理。Luna 仍可能有工具续等开销，不能宣称完全免费。

单个格式重试耗尽后执行槽继续本轮其他独立任务，轮末一次返回所有异常；不可重试服务故障仍暂停。主对话等待规则不变，不为单批中间失败唤醒主对话。
