# AINiee 翻译配置参考

> 基于本仓库 `Tools/AINiee` 源码分析，针对游戏文本汉化的防占位符破坏配置。

## 启动

```powershell
cd Tools\AINiee
.\venv\Scripts\python.exe AiNiee.py
```

需要 Python 3.12 虚拟环境（已建于 `Tools/AINiee/venv/`）。在「接口管理」添加并激活 API（推荐 DeepSeek）。

## 防占位符破坏：两个必须同时开启的开关

### 1. 禁翻表（左侧导航「禁翻表」）

- 顶部开关打开（配置键 `exclusion_list_switch`）
- 表格三列：**标记符** | **备注** | **正则**
  - 标记符：字面字符串，文本中含有即触发（会被 `re.escape`）
  - 正则：匹配即触发，优先级高于标记符
- **触发机制**：文本含有标记符，或正则表达式匹配生效
- 作用（`PromptBuilder.build_ntl_prompt`）：扫描当前批次原文，把命中的标记符写入系统提示词，明确告知 AI「以下内容禁止翻译」
- 编辑后必须点工具栏**保存按钮**
- 支持**导入** JSON/XLSX：JSON 为对象数组，键为 `markers`/`info`/`regex`。`analyze_placeholders.py` 生成的 `ainiee_exclusion_list.json` 可直接导入

### 2. 自动处理文本代码段（「翻译设置」页面）

- 配置键 `auto_process_text_code_segment`，默认 **关闭**，必须手动打开
- 界面描述：「启用此功能后，根据正则库与禁翻表，将在翻译前移除文本首尾的非翻译内容，占位文本中间的非翻译内容，并在翻译后还原」
- 工作机制（`TextProcessor`）：
  - 译前：把命中（内置正则库 + 禁翻表）的内容替换为 `[P0]`、`[P1]` 占位符，AI 根本看不到原始标记 —— 这是比禁翻表提示词更强的**硬保障**
  - 译后：自动还原占位符为原始标记
  - 每个翻译任务最多处理 50 个占位匹配，超出部分不保护（单批次文本标记数一般远低于此）
  - Sakura 接口用 `↓` 系列占位，其他接口用 `[P数字]`

### 内置正则库（`Resource/Regex/regex.json`）

内置规则主要覆盖 **RPG Maker** 控制码（`\C[1]`、`\N[1]`、`{color=...}` 等），**不覆盖**各游戏自定义的 `[Xxx:Yyy]`、`{0}`、`%s` 等格式。**任何非 RPG Maker 游戏都必须用 analyze_placeholders.py 生成并导入禁翻表。**

## 其他相关设置

| 设置 | 位置 | 说明 |
|------|------|------|
| 术语表 | 左侧导航 | 固定译名（人名/地名/技能名），保证全文一致 |
| 文本替换（译前/译后） | 左侧导航 | 正则替换，可修正 AI 习惯性错译 |
| 提示词设置 | 提示词页面 | 可追加自定义指令，如「保留所有方括号标记原样」 |
| 行数/换行处理 | 内置 | AINiee 会统一换行符并还原，但仍可能把字面 `\n` 译成真实换行，需译后校验 |

## 已知坑

1. **字面 `\n` 变真实换行**：AI 会把文本中的 `\n` 两字符转义写成真实换行符，导致 CSV 物理行数膨胀、按行读取的回填脚本错位。`validate_translation.py --fix-newlines` 可修复。
2. **全角化**：AI 会把 `[...]` 写成 `【...】`，把 `:` 写成 `：`。禁翻表 + 自动占位可根治。
3. **变量名改写**：AI 会把 `[Upset:Name]` 简化为 `[Name]`、`[VoiceOfReason:him/her]` 改为 `[VoiceOfReason:he/she]`。硬占位（自动处理文本代码段）可根治。
4. **花括号陷阱**：部分游戏（如 Expeditions Viking）用 `{...}` 包裹**需要翻译**的玩家选项文本。不要把通用 `\{[^{}]*\}` 加进禁翻表，否则选项文本会原样输出英文。只需保护机器型花括号：`{0}`、`{name}`、`{key=value}`。
5. **配置存储**：禁翻表等设置保存在 AINiee 的 `Resource/config.json`，按项目共享，换游戏翻译时记得更新禁翻表。
