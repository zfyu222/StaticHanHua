## 范围

最初仅修改隔离工作树的共用流程程序与说明；未修改 Torment 游戏项目的源文、译文、任务、术语、API 配置、运行状态或正在执行的 runner。隔离验证时尚未合入共享工具目录；后续主干集成状态见文末记录。保持思考开启，未修改用户配置中的并发。

此前只读审计观察到：独立审校已知用量约 116.5M Token，其中输入约 35.6M、可见输出约 16.2M、思考约 64.7M；故只缩短 JSON 不能解决主要成本。普通词被全局当术语，会让模型反复解释例外；重复举证及格式返修则增加输出与尾部调用。本次实现对应用户批准的三项改进，没有取消任何语义检查。

## 实现

### 1. 收紧术语适用范围

- 提取及术语审校明确区分游戏专名、游戏特定义与普通词义，频率高不构成术语依据。
- 新术语快照对 I、like、back、might、may、will、普通代词、单字母等歧义项设置范围门槛：必须提供有出处依据的适用范围，或隔离；不能只承认风险却保留为无范围全局条目。
- `applicability` 支持正文匹配、完整标签匹配、紧邻字串上下文匹配，分别保留大小写设置与具体理由。更改范围必须提交实际出处行。
- 匹配先判断范围再处理重叠；一批多条记录仍逐条判断，不能把另一条记录的上下文当作当前证据。
- 例如 `Might` 可限定为完整属性标签，不匹配 `I might return tomorrow.`；`May` 人名可按大小写匹配，不强制改写 `You may enter.`。
- 旧冻结快照保持原有含义，不在本次开发中自动改写已有游戏术语。歧义词集合是风险提示和准入规则的一部分，并非穷尽普通词的语义分类器；是否属于真正术语仍须实际审校。

### 2. 保留六维，复用相同证据

- 每条记录可提供自己的 `evidence={"e1":"具体核对依据"}`，由 `reason`、六维检查的证据和修改理由显式引用。
- 六维状态仍逐个由模型填写；程序只展开模型实际提供的文字，不生成状态、判断或依据。
- 未知引用、跨记录引用、嵌套引用、空依据、未使用的证据表项均拒绝；缺少维度仍拒绝。
- 仅在同一证据确实支持多个维度时复用；若依据不同，仍需分别提供。
- 完整共同结果仍保存展开后的证据，原始 API 回复继续保留。

### 3. 确定性格式恢复

- 新任务采用 `exact_v1` 策略：仅还原绑定源文的首尾空格/制表符，以及段落数一致时的 CRLF/LF/CR 编码。
- 有源文哈希绑定的记录约束时，遵守该约束指定的物理换行；哈希不一致即拒绝。
- 不插入、删除或移动段落，不猜标签、变量、空文本或语义；锁定记录不调整。
- 若模型明确声称修正占位符/格式，或修改依据与候选无法绑定，保留原结果给已有验收链判断，不覆盖该声称。
- 不擦除模型声称的修改，不补写语义检查。每次实际恢复记录源文与前后哈希及策略审计事件。
- 批量收集与直接提交共用处理入口；旧任务没有策略标记时仍沿用严格旧行为。

- 提取、术语审校、独立审校分别接收 1 批，失败 0。
- 6/6 条记录实际使用了记录内证据引用，并保留六维独立状态。

## 后续应用与边界

已完成可审查的隔离实现。共用代码合入不等于迁移正在运行的游戏项目；新术语范围需要经过实际原文审校，现有冻结术语不会自动迁移。只有完成范围审校并冻结的新快照，才能减少该游戏中已存在的普通词假命中。没有必要为启用证据引用而重派已通过审校。

实际收益应在相同接口、相近文本与既有预算下，比较普通词例外数、每条思考/可见输出 Token、格式返修请求数、首轮通过率和墙钟时间。保持原语义门槛与停止条件，不通过取消思考、减少维度或自动填 pass 换取表面节省。
