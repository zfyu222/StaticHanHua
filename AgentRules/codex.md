# Codex 专属规则

公共工作流（AGENTS.md 与 skills）只写通用要求；本文件记录 Codex 的具体做法。本目录不参与 `sync_agent_compat.bat` 同步。

## 模型档位

| 档位 | 模型 |
|------|------|
| 便宜档 `cheap` | 最新 luna（当前为 `gpt-6-luna`） |
| 标准档 `standard` | 最新 sol（当前为 `gpt-6-sol`） |

创建子代理时取该系列当前最新版本。

## 子代理

- 用 `spawn_agent` 创建，固定 `fork_turns=none`，不继承主对话历史。
- 每批一个新实例；验收后结束，下一批重新 `spawn_agent`，不能 `followup_task` 给已完成实例继续下一批。
- `claim --worker` / `batch-open --workers` 使用 `spawn_agent` 返回的实际 agent ID。
- 主代理用宿主的 `wait_agent` 等待子代理完成事件。

## 长耗时任务等待（API 阶段）

API 阶段由一个新的便宜档执行代理运行 `run_api_round.py`，主代理派发一次后进入原生代理等待。

1. 创建便宜档、`fork_turns=none` 的执行代理。只交付绝对项目路径、阶段、Python 路径、下面的执行模板和必要的显式恢复 session ID。不要复制主对话历史、术语表、批次 JSON、API 密钥或日志。普通翻译 API 的模型仍由 api.local.jsonc 决定；便宜档是程序执行角色，不冒充正文 API 模型。
2. 主代理用 `wait_agent` 或同等原生等待接收完成事件。等待挂起期间不主动推理检查状态，不调用 list_agents、status、tail、write_stdin 或读取 receipt 来探测进度；不反复询问执行代理，也不用周期 Sleep 猜测程序是否结束。保持本轮对话等待，不先发 final 后假设外部文件能自动唤醒聊天。
3. 等待时长在宿主允许范围内尽量延长；宿主有更高优先级的最大等待或沟通约束时按其上限设置。等待超时而没有事件，只继续原生等待，不追加状态查询或“还没完成”的分析。
4. 完成后释放本阶段执行代理，下一阶段调用新建，避免监控历史累积。没有可用便宜档槽位时先等待现有代理结束；不要额外创建标准档调度代理。
5. 回执文件本身不是唤醒事件；真正通知来自执行代理的原生完成事件。执行代理仍可能有工具续等开销，不能宣称完全免费。宿主不支持原生代理等待时明确说明能力缺口，退回有界工具等待，不假称具备事件回调。

### 给便宜档执行代理的最小模板

> 你只负责运行一个 API 阶段的自动常规循环，并等待该进程结束。项目：`<绝对路径>`；阶段：`<stage>`；Python：`<绝对路径>`。
>
> 执行一次：`<python> D:/StaticHanHua/Tools/localization/run_api_round.py --project <project> --stage <stage>`。以工具的参数数组或正确 shell 引号传递路径，不拼接不可信命令。显式恢复时才附主流程已核实的 `--sessions <IDs...>`。
>
> runner 自行阻塞等待子进程，日志留在项目内；不再启动第二个 runner，不运行 status/tail 或定时读取文件。优先使用阻塞式工具等待。如果命令工具返回 session ID，在同一程序化工具调用内以 await 等待该 session 结束，必要的有界续等留在执行代理，不逐次上报给主代理。不要把短间隔轮询搬到你的推理中。
>
> 按用户原优先级运行，不自行添加 `--api`；只有主流程同时提供用户明确指定该接口的授权依据时才允许固定接口。错误不构成切换官方、修改优先级或增加请求/Token/尝试预算的授权。收到用户停止消耗的指令时立即终止本任务 runner 及其子进程，不重试、不恢复。
>
> 不查看密钥文件，不翻译或修改结果，不跑质量裁决，不自行额外执行命令、切换阶段或放宽门槛；本阶段普通修复轮由 runner 内部程序自动推进。错误、锁冲突、不明在途请求及标准档升级均只报告，不自行重放付费请求。
>
> 等待期间不向主代理发送心跳、进度或“仍在运行”；只在完成、失败或需决策时发送一次终结结果。返回 `status`、`stage`、`receipt_file`、简短计数/阻塞原因；不返回原文、整批译文、提示词或完整日志。不需要调用 send_message；原生最终结果通知即可。
